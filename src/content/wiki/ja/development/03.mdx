では、いよいよウィキページの作成に取り掛かっていきます。

## 構成
`./src/content/wiki/[locale]`配下に各記事のmdxファイルを配置し、コレクションローダーで収集したものを、`./src/pages/[locale]/wiki/[...slug].astro`でページに変換します。  

## mdx
まずは、mdxファイルを取り扱うためのインテグレーションを追加します。  
mdxによって、markdown内でjsxやコンポーネントを利用できるようになります。

```sh
npx astro add mdx
```

## コレクションローダー
ウィキページ用のコレクションローダーを`./src/content.config.ts`として作成し、`src`直下に配置します。  
`./src/content/wiki`配下にある、`.md`または`.mdx`ファイルを収集し、`wiki`コレクションとして利用できるように定義します。

```ts
import { defineCollection } from "astro:content";
import { glob } from "astro/loaders";
import { z } from "astro/zod";

const wiki = defineCollection({
    loader: glob({ base: './src/content/wiki', pattern: '**/*.{md,mdx}'}),
    schema: z.object({
        title: z.string(),
        description: z.string().optional(),
        order: z.number().default(0),
        aliases: z.array(z.string()).default([]),
        tags: z.array(z.string()).default([]),
        date: z.coerce.date().optional(),
        updated: z.coerce.date().optional(),
        draft: z.boolean().default(false),
        hasToc: z.boolean().default(true),
        subpage: z.boolean().default(false),
    }),
});

export const collections = { wiki };
```

以下、schemaの各項目の説明です。
- `title`: ページのタイトル（必須）
- `description`: ページの説明（任意）
- `order`: ページの表示順（数値が小さい方が上に表示される）（任意、デフォルト0）
- `aliases`: ページの別名（任意）
- `tags`: ページのタグ（任意）
- `date`: ページの作成日（YYYY-MM-DD形式）（任意）
- `updated`: ページの更新日（YYYY-MM-DD形式）（任意）
- `draft`: ドラフトフラグ（true/false）（任意、デフォルトfalse）
- `hasToc`: 目次表示フラグ（true/false）（任意、デフォルトtrue）
- `subpage`: サブページフラグ（true/false）（任意、デフォルトfalse）

## ユーティリティ関数
`@lib/slug.ts`に、スラッグ関連のユーティリティ関数を記述します。

### divideId()
ページIDを分割して、ロケールと生のベーススラッグを抽出する関数です。

```ts
import type { Locale } from '@i18n/i18n.config';
import { isLocale } from "@lib/locale";

export function dividePageId(pageId: string): {locale: Locale, rawBaseSlug: string} {
    const parts = pageId.split('/');
    if (isLocale(parts[0])) {
        return {
            locale: parts[0],
            rawBaseSlug: parts.slice(1).join('/')
        };
    }
    throw new Error(`[Invalid id format] ${pageId}`);
}
```

- ページIDは`./src/content/wiki/`以下のパスです。この直下に各ロケールのディレクトリを配置し、その下にページを配置する構成を取っているので、ページIDをロケール部分とベーススラッグ部分に分離できます。  
- ページIDを`.split('/')`で分割すると、最初の要素がロケール、残りがベーススラッグになります。  
- `isLocale()`関数でページIDから取得したロケールが実際に`@i18n/i18n.config.ts`で設定したロケールの対象かどうかをチェックします。

### normalizeSlug()
スラッグを正規化する関数です。

```ts
export function normalizeSlug(rawSlug: string): string {
    const normalized = rawSlug.normalize('NFKC').toLowerCase().trim();
    return normalized === 'index'
        ? ''
        : normalized.replace(/\/index$/, '');
}
```

## 動的ルーティング
`./src/pages/[locale]/wiki/[...slug].astro`を作成し、動的ルート用のページとします。   
- スラッグ部分は`[...slug]`のレストパラメータ形式を採用することで、任意の深さのスラッグにマッチします。  
`getStaticPaths()`関数で`locale`と`slug`を出力することで、対応するページのパスを生成します。  

### getStaticPaths()
`getStaticPaths()`関数では、パス生成のために各ページの`locale`と`slug`を出力する必要があります。  

まず、`getCollection()`関数を用いて、`wiki`コレクションから`draft`フラグが`false`のページ（下書きではないページ）を全て収集します。  

```ts
const wikiPages = await getCollection('wiki', (page) => !page.data.draft);
```

#### ページデータ格納
収集した各ページについて、ページIDから`dividePageId()`関数を用いて`locale`と`rawBaseSlug`を取得し、さらに`rawBaseSlug`は`normalizeSlug()`関数を用いて`normalizedBaseSlug`に正規化します。  
同じ記事の各言語版を紐づけるため、`normalizedBaseSlug`と`locale`をキーとして`pagesByBaseSlug`に格納します。

```ts
const pagesByBaseSlug: Record<string, Partial<Record<Locale, CollectionEntry<'wiki'>>>> = {};

for (const page of wikiPages) {
    const { locale, rawBaseSlug } = dividePageId(page.id);
    const normalizedBaseSlug = normalizeSlug(rawBaseSlug);
    if (!pagesByBaseSlug[normalizedBaseSlug]) {
        pagesByBaseSlug[normalizedBaseSlug] = {};
    }
    pagesByBaseSlug[normalizedBaseSlug][locale] = page;
}
```

#### 衝突検証
もし複数の異なるファイルが同じ`normalizedBaseSlug`に正規化される場合、後から処理された方が先に処理された方を上書きしてしまうため、これを検出してビルドエラーにします。  
そこで、正規化後のページIDと正規化前のページIDを紐づけて`normalizedIdOwners`に保存します。  
もし正規化による衝突が起きる場合は、同じ`normalizedId`に対して複数の`page.id`が登録されるため、`normalizedIdOwners`の各要素の`size`が1より大きくなるので、これを検出してエラーを投げます。  
- なお、衝突判定は同一ロケール内だけで行う必要があるため、ベーススラッグではなく、ロケール情報を含むページIDの正規化前後を比較しています。

```ts
const normalizedIdOwners: Record<string, Set<string>> = {};
for (const page of wikiPages) {
    const normalizedId = normalizeSlug(page.id);
    
    if (!normalizedIdOwners[normalizedId]) {
        normalizedIdOwners[normalizedId] = new Set();
    }
    normalizedIdOwners[normalizedId].add(page.id);
}
for (const [normalizedId, owners] of Object.entries(normalizedIdOwners)) {
    if (owners.size > 1) {
        throw new Error(`[wiki routing] Multiple owners for normalized ID "${normalizedId}": ${Array.from(owners).join(', ')}`);
    }
}
```

#### paths
衝突検証が完了したら、`pagesByBaseSlug`に格納したデータから、各ページのURLパス構築に必要な`locale`および`baseSlug`の取得、フォールバック判定を`paths`に格納していきます。  
まず、各`normalizedBaseSlug`について、利用可能なロケールのページを取得し、`availablePages`に格納します。  
さらに、各`locale`について、`normalizedBaseSlug`を`slug`に設定します。ただし、`normalizedBaseSlug`が空文字の場合は`slug`を`undefined`に設定します。  
`availablePages`に対応する`locale`のページが存在しない場合は`isFallback`を`true`に、存在する場合は`isFallback`を`false`に設定します。  
`availablePages`に`locale`が存在する場合はそのページを、`locale`が存在せず`defaultLocale`が存在する場合は`defaultLocale`のページを、`locale`も`defaultLocale`も存在しない場合、存在するうちの最初のページを`page`に設定します。  
最後に、`paths`の`params`に`locale`と`slug`を、`props`に`page`、`locale`、`baseSlug`、`isFallback`を格納します。

```ts
const paths: { params: { locale: Locale; slug: string | undefined }; props: Props }[] = [];
for (const baseSlug of Object.keys(pagesByBaseSlug)) {
    const availablePages = pagesByBaseSlug[baseSlug];
    for (const locale of locales) {
        const slug = baseSlug === ''
            ? undefined
            : baseSlug;
        const isFallback = !availablePages[locale];
        const page = availablePages[locale]
            ?? availablePages[defaultLocale]
            ?? Object.values(availablePages)[0];

        paths.push({
            params: { locale, slug },
            props: {
                page,
                locale,
                baseSlug,
                isFallback,
            }
        })
    }
}
```

#### 出力
`paths`を出力します。

```ts
return paths;
```
