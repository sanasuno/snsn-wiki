では、いよいよウィキページの作成に取り掛かっていきます。

## 構成
`./src/content/wiki/[locale]`配下に各記事のmdxファイルを配置し、コレクションローダーで収集したものを、`./src/pages/[locale]/wiki/[...slug].astro`でページに変換します。  


## mdx
まずは、mdxファイルを取り扱うためのインテグレーションを追加します。  
mdxによって、markdown内でjsxやコンポーネントを利用できるようになります。

```sh
npx astro add mdx
```

## コレクションローダー
ウィキページ用のコレクションローダーを`content.config.ts`として作成し、`src`直下に配置します。  
`./src/content/wiki`配下にある、`.md`または`.mdx`ファイルを収集し、`wiki`コレクションとして利用できるように定義します。

```ts
import { defineCollection } from "astro:content";
import { glob } from "astro/loaders";
import { z } from "astro/zod";

const wiki = defineCollection({
    loader: glob({ base: './src/content/wiki', pattern: '**/*.{md,mdx}'}),
    schema: z.object({
        title: z.string(),
        description: z.string().optional(),
        order: z.number().default(0),
        aliases: z.array(z.string()).default([]),
        tags: z.array(z.string()).default([]),
        date: z.coerce.date().optional(),
        updated: z.coerce.date().optional(),
        draft: z.boolean().default(false),
        subpage: z.boolean().default(false),
    }),
});

export const collections = {
    wiki,
};
```

以下、schemaの各項目の説明です。
- `title`: ページのタイトル（必須）
- `description`: ページの説明（任意）
- `order`: ページの表示順（数値が小さい方が上に表示される）（任意、デフォルト0）
- `aliases`: ページの別名（任意）
- `tags`: ページのタグ（任意）
- `date`: ページの作成日（YYYY-MM-DD形式）（任意）
- `updated`: ページの更新日（YYYY-MM-DD形式）（任意）
- `draft`: ドラフトフラグ（true/false）（任意、デフォルトfalse）
- `subpage`: サブページフラグ（true/false）（任意、デフォルトfalse）

## 動的ルーティング
`./src/pages/[locale]/wiki/[...slug].astro`を作成し、動的ルート用のページとします。   
- ファイル名に`[...slug]`のレストパラメータ形式を採用することで、任意の深さにマッチします。  
`getStaticPaths()`関数で`locale`と`slug`を出力することで、対応するページのパスを生成します。  

### getStaticPaths()
`getStaticPaths()`関数では、パス生成のために各ページの`locale`と`slug`を出力する必要があります。  

まず、`getCollection()`関数を用いて、`wiki`コレクションから`draft`フラグが`false`のページを収集します。  
次に、収集した各ページの`id`をもとに`locale`と`baseSlug`を抽出し、`pagesByBaseSlug`に格納します。  
さらに、URL衝突の検証を行うために、URL上の位置を`routeKey`として抽出し、`routeKeyOwners`に格納します。  

```ts
const pages = await getCollection('wiki', (page) => !page.data.draft);
const pagesByBaseSlug: Record<string, Record<string, CollectionEntry<'wiki'>>> = {};
const routeKeyOwners: Record<string, Set<string>> = {};
```

#### divideId
`id`から`locale`と`baseSlug`を抽出する関数を、`@lib/locale.ts`に作成します。  
`id`は`./src/content/wiki`配下のファイルパスを表します。  
このディレクトリの下に各ロケールごとのディレクトリがあるので、`id`を`/`で分割し、最初の要素を`locale`、残りを`baseSlug`として抽出します。  
Astroのルーティングでは、`index.mdx`はルートパスとして扱われるため、`baseSlug`から`index`を削除して正規化する必要があります。  
また、`locale`が`locales`に含まれていることを確認する必要があるので、この部分を別の関数として切り出します。

```ts
import { locales } from "@i18n/i18n.config"
export function isLocale(value: string): value is Locale {
    return locales.includes(value as Locale)
}
```

```ts
import { type Locale } from "@i18n/i18n.config"
export function divideId(id: string): {locale: Locale, rawBaseSlug: string} {
    const parts = id.split('/');
    if (isLocale(parts[0])) {
        return {
            locale: parts[0],
            rawBaseSlug: parts.slice(1).join('/')
        };
    }
    throw new Error(`[Invalid id format] ${id}`);
}
```

#### ページデータ格納
`divideId()`関数を用いて`locale`と`baseSlug`を取得したら、`baseSlug`を`normalizedBaseSlug`に正規化してから、`pagesByBaseSlug`に`normalizedBaseSlug`と`locale`をキーとして、ページデータを`pagesByBaseSlug`に格納します。  
さらに、URL衝突の検証用に、実際のURLの位置を`routeKey`として、`routeKeyOwners`に格納します。  
実際のURLでは、`index`ファイル名のページは省略されるため、`page.id`末尾の`/index`を削除します。  
`routeKey`をキー、`baseSlug`を値として`routeKeyOwners`に格納します。これにより、異なる`baseSlug`（＝異なるファイル）が同じ`routeKey`を持つ場合、URLが衝突することがわかります。

```ts
for (const page of pages) {
    const { locale, rawBaseSlug } = divideId(page.id);
    const normalizedBaseSlug = normalizeSlug(rawBaseSlug);
    if (!pagesByBaseSlug[normalizedBaseSlug]) {
        pagesByBaseSlug[normalizedBaseSlug] = {};
    }
    pagesByBaseSlug[normalizedBaseSlug][locale] = page;
    
    const routeKey = normalizeSlug(page.id);
    
    if (!routeKeyOwners[routeKey]) {
        routeKeyOwners[routeKey] = new Set();
    }
    routeKeyOwners[routeKey].add(rawBaseSlug);
}
```

#### ルート検証
すべてのページについてこの操作が完了したら、URL検証を行います。  
`routeKeyOwners`に格納した各`routeKey`について、`routeKeyOwners[routeKey]`のサイズが1より大きい場合、つまり異なる`baseSlug`が同じ`routeKey`を持つ場合、URLが衝突しているので、エラーを投げます。

```ts
for (const [routeKey, owners] of Object.entries(routeKeyOwners)) {
    if (owners.size > 1) {
        throw new Error(`[wiki routing] Multiple owners for route slug "${routeKey}": ${Array.from(owners).join(', ')}`);
    }
}
```

#### paths
URL検証が完了したら、`pagesByBaseSlug`に格納したデータから、各ページのURLパス構築に必要な`locale`および`baseSlug`の取得、フォールバック判定を`paths`に格納していきます。  
まず、各`normalizedBaseSlug`について、利用可能なロケールのページを取得し、`availablePages`に格納します。  
さらに、各`locale`について、`normalizedBaseSlug`を`slug`に設定します。ただし、`normalizedBaseSlug`が空文字の場合は`slug`を`undefined`に設定します。  
`availablePages`に対応する`locale`のページが存在しない場合は`isFallback`を`true`に、存在する場合は`isFallback`を`false`に設定します。  
`availablePages`に`locale`が存在する場合はそのページを、`locale`が存在せず`defaultLocale`が存在する場合は`defaultLocale`のページを、`locale`も`defaultLocale`も存在しない場合、存在するうちの最初のページを`page`に設定します。  
最後に、`paths`の`params`に`locale`と`slug`を、`props`に`page`、`locale`、`baseSlug`、`isFallback`を格納します。

```ts
const paths: { params: { locale: Locale; slug: string | undefined }; props: Props }[] = [];
for (const baseSlug of Object.keys(pagesByBaseSlug)) {
    const availablePages = pagesByBaseSlug[baseSlug];
    for (const locale of locales) {
        const slug = baseSlug === ''
            ? undefined
            : baseSlug;
        const isFallback = !availablePages[locale];
        const page = availablePages[locale]
            ?? availablePages[defaultLocale]
            ?? Object.values(availablePages)[0];

        paths.push({
            params: { locale, slug },
            props: {
                page,
                locale,
                baseSlug,
                isFallback,
            }
        })
    }
}
```

#### 出力
`paths`を出力します。

```ts
return paths;
```
